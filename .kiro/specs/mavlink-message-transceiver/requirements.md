# MAVLink 메시지 송수신 기능 요구사항

## 개요
MAV-Flow Flutter Windows Desktop 앱에 MAVLink 프로토콜 기반 메시지 송수신 기능을 추가합니다. 기존 시리얼 모니터링 기능을 MAVLink 표준으로 확장하여 다양한 장치 역할(gen3, mc, fcc, gcs)에 따른 메시지 송수신을 지원합니다.

---

## 기능 요구사항

### FR-1: MAVLink 메시지 수신 및 파싱

**FR-1.1**: 시스템은 시리얼 포트를 통해 MAVLink v2 프로토콜 형식의 바이너리 메시지를 수신해야 합니다.

**FR-1.2**: 수신된 MAVLink 메시지를 메시지 ID에 따라 파싱하고, 파싱된 필드 값을 Data Table에 업데이트해야 합니다.

**FR-1.3**: 파싱된 각 필드는 `{MessageName}.{FieldName}` 형식의 TAG로 식별되어야 합니다 (예: `HEARTBEAT.type`, `SYS_STATUS.voltage_battery`).

**FR-1.4**: 수신 화면에서 Data Table의 값을 실시간으로 조회할 수 있어야 하며, MAVLink 메시지 규격에 따라 label(필드명), 값, 설명을 표시해야 합니다.

---

### FR-2: MAVLink 메시지 생성 및 전송

**FR-2.1**: 사용자가 송신 화면에서 전송할 MAVLink 메시지를 목록에서 선택할 수 있어야 합니다.

**FR-2.2**: 선택된 메시지의 필드 값을 Data Table에서 읽어와 송신 화면에 표시해야 합니다.

**FR-2.3**: 사용자가 송신 화면에서 각 필드의 값을 직접 수정할 수 있어야 합니다.

**FR-2.4**: 전송 버튼을 누르면 현재 필드 값으로 MAVLink 메시지를 생성하여 시리얼 포트로 전송해야 합니다.

**FR-2.5**: 자동전송 기능을 활성화하면 지정된 주기(기본값 500ms)에 따라 메시지를 반복 전송해야 합니다.

**FR-2.6**: 자동전송 주기는 사용자가 변경할 수 있어야 합니다.

---

### FR-3: 역할 기반 메시지 설정

**FR-3.1**: 시스템은 4가지 역할(장치)을 지원해야 합니다: `gen3`, `mc`, `fcc`, `gcs`.

**FR-3.2**: 설정 파일에서 각 역할별로 송신할 메시지 목록과 수신할 메시지 목록을 정의해야 합니다.

**FR-3.3**: 화면 상단에서 현재 역할을 선택할 수 있어야 하며, 선택된 역할에 따라 송신 가능한 메시지 목록이 결정되어야 합니다.

---

### FR-4: 통신 인터페이스

**FR-4.1**: 현재 버전에서는 시리얼 통신만 지원합니다.

**FR-4.2**: 기존 SerialService를 재활용하되, MAVLink 프레임 동기화(0xFD 헤더) 및 송신 기능을 추가해야 합니다.

**FR-4.3**: 향후 TCP, UDP 통신 확장을 고려하여 통신 인터페이스를 추상화해야 합니다.

---

### FR-5: MAVLink 메시지 규격 관리

**FR-5.1**: MAVLink 표준 XML 파일(common.xml 등)을 메시지 규격의 원본으로 사용해야 합니다.

**FR-5.2**: 확장/사용자 정의 메시지도 MAVLink XML 형식으로 작성하여 관리해야 합니다.

**FR-5.3**: 앱 시작 시 XML 파일을 파싱하여 JSON 형식으로 변환 및 저장하고, 런타임에서는 JSON만 참조해야 합니다.

**FR-5.4**: 설정/관리 화면에서 "메시지 규격 변환" 버튼을 제공하여 XML을 재파싱하고 JSON을 갱신할 수 있어야 합니다.

**FR-5.5**: 기존 `assets/message_spec.yaml` 파일은 삭제하고 MAVLink XML/JSON 방식으로 대체해야 합니다.

**FR-5.6**: 현재 버전에서는 MAVLink 표준 메시지만 처리하며, 사용자 정의 메시지 규격은 추후 제공됩니다.

---

### FR-6: 화면 레이아웃

**FR-6.1**: 화면 상단에 역할(장치) 선택 드롭다운을 배치해야 합니다 (`gen3`, `mc`, `fcc`, `gcs`).

**FR-6.2**: 메인 영역은 좌/우로 분할하여 수신 화면과 송신 화면을 동시에 표시해야 합니다.

**FR-6.3**: 수신 화면에서는 수신된 MAVLink 메시지의 필드 값을 Data Table 형태로 표시해야 합니다.

**FR-6.4**: 송신 화면에서는 다음 기능을 제공해야 합니다:
  - 전송할 메시지 목록 선택 (전체 데이터 또는 선택된 메시지의 데이터만 표시)
  - Data Table 조회 및 필드 값 변경
  - 수동 전송 버튼
  - 자동전송 메시지 목록 표시 (전송 주기, ON/OFF 제어, 주기 변경)

**FR-6.5**: 설정/관리 화면에서 "메시지 규격 변환" 버튼을 제공해야 합니다.

---

### FR-7: Data Table 설계

**FR-7.1**: 수신 화면과 송신 화면에서 동일한 Data Table 구조를 공유해야 합니다.

**FR-7.2**: 각 필드에 대해 현재값(수신된 값)과 전송값(사용자가 변경할 값)을 구분하여 관리해야 합니다.

**FR-7.3**: Data Table의 TAG는 `{MessageName}.{FieldName}` 형식을 사용해야 합니다 (예: `HEARTBEAT.type`, `SYS_STATUS.voltage_battery`).

---

## 비기능 요구사항

### NFR-1: 성능

**NFR-1.1**: MAVLink 메시지 수신 및 파싱은 UI를 블로킹하지 않아야 합니다 (백그라운드 Isolate 활용).

**NFR-1.2**: 자동전송 타이머는 지정된 주기를 ±10ms 이내로 준수해야 합니다.

---

### NFR-2: 확장성

**NFR-2.1**: 통신 인터페이스는 향후 TCP, UDP 추가를 위해 추상화 계층을 제공해야 합니다.

**NFR-2.2**: 새로운 MAVLink 메시지 추가 시 XML 파일만 수정하면 앱에 반영되어야 합니다.

---

### NFR-3: 유지보수성

**NFR-3.1**: MAVLink 메시지 규격은 MAVLink 표준 XML 형식을 그대로 사용하여 공식 문서와의 호환성을 유지해야 합니다.

**NFR-3.2**: 역할별 메시지 설정은 별도 설정 파일로 분리하여 관리해야 합니다.

---

## 용어 정의

| 용어 | 설명 |
|------|------|
| MAVLink | Micro Air Vehicle Link, 드론 및 무인 시스템을 위한 경량 통신 프로토콜 |
| MAVLink v2 | MAVLink 프로토콜 버전 2, 헤더 바이트 0xFD 사용 |
| gen3 | Communication Gateway 3세대 (데이터 수집, 프로토콜 변환, 메시지 전달) |
| mc | Mission Computer 역할 |
| fcc | Flight Control Computer 역할 |
| gcs | Ground Control Station 역할 (지상관제) |
| Data Table | 메시지 필드의 현재값과 전송값을 저장하는 내부 데이터 구조 |
| TAG | 필드를 고유하게 식별하는 문자열 (`{MessageName}.{FieldName}` 형식) |

---

## 제약 사항

1. 현재 버전에서는 시리얼 통신만 지원하며, TCP/UDP는 향후 버전에서 추가됩니다.
2. 사용자 정의 MAVLink 메시지 규격은 현재 제공되지 않으며, 표준 메시지(common.xml)만 처리합니다.
3. Windows Desktop 플랫폼만 지원합니다.

---

## 사용 시나리오

이 프로그램은 여러 개의 인스턴스를 동시에 실행하여 각 인스턴스가 하나의 장치(역할)를 담당하도록 구성할 수 있습니다. 실제 H/W 장치 하나와 나머지 주변 장치를 이 프로그램으로 시뮬레이션하여 실제 장치의 동작을 검증하는 용도로 사용됩니다.

예시:
- 인스턴스 1: gen3 역할 (실제 H/W 장치)
- 인스턴스 2: fcc 역할 (시뮬레이션)
- 인스턴스 3: gcs 역할 (시뮬레이션)
